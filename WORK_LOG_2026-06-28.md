## 2. Fix #1 — Class-weighted loss (implemented, tested, decided)

**What I built:** a `WeightedTrainer` that overrides `compute_loss` with
`CrossEntropyLoss(weight=class_weights)`, where weights are the **inverse class frequency**
(`sklearn compute_class_weight('balanced')`). Computed weights (rare class = higher weight):

| Class | Weight |
|---|---|
| Personality disorder | 8.16 |
| Stress | 3.18 |
| Bipolar | 2.92 |
| Anxiety | 2.02 |
| Suicidal | 0.69 |
| Depression | 0.48 |
| Normal | 0.46 |

**What I did:** actually **retrained RoBERTa** with this loss on the RTX 4060 (3 epochs, same
hyper-parameters), then evaluated on the 7,659-sample test set.

**Measured result (honest):**

| Metric | Plain (final) | Weighted |
|---|:---:|:---:|
| Accuracy | **0.823** | 0.804 |
| Weighted-F1 | **0.823** | 0.805 |
| Macro-F1 | **0.783** | 0.766 |
| Suicidal — recall | 0.75 | **0.81** |
| Stress — recall | 0.75 | **0.83** |
| Personality disorder — recall | 0.55 | **0.61** |
| Depression — recall | **0.75** | 0.67 |

**Interpretation:** weighting raised **recall on most at-risk minority classes** (catches more of
them) but lowered **precision** and overall **accuracy** — the classic precision–recall trade-off.
It did **not** improve macro-F1.

**Decision (yours):** keep the **plain RoBERTa as the final model**; report the weighted run as an
**ablation**. This keeps the headline intact and is a stronger, honest research story (a real
experiment, not a claim).
